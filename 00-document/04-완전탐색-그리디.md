# 04. 완전탐색 · 그리디

> 목표: 가능한 경우를 빠짐없이 탐색하거나, 선택이 최적인 이유를 증명해 탐색 범위를 줄인다.

## 핵심 개념

- **완전탐색**은 가능한 후보를 모두 살펴본다. 입력 크기로 경우의 수를 계산하고 반복문, 순열·조합, DFS/백트래킹 중 표현하기 쉬운 방법을 고른다. 가지치기는 답이 될 수 없는 경우에만 적용한다.
- **그리디**는 매 단계에서 선택을 확정한다. 정렬이나 우선순위 큐를 자주 사용하지만, 직관만으로는 정답이 보장되지 않는다. 교환 논증, 불변식 또는 반례 검토로 선택의 타당성을 확인한다.
- Python의 `itertools.permutations`, `combinations`, `product`는 후보 생성에 유용하다. 생성 개수와 각 후보의 검사 비용을 함께 계산한다.

## 단계별 훈련

### 1단계 · 기초

- [ ] 프로그래머스 모의고사 — 모든 패턴의 점수 비교
- [ ] 프로그래머스 최소직사각형 — 방향을 통일해 후보를 단순화
- [ ] 프로그래머스 체육복 — 중복 조건을 정리하고 대여 순서 검증
- [ ] 작은 입력을 직접 열거해 그리디 결과와 완전탐색 결과를 비교

### 2단계 · Lv.2 패턴

- [ ] 카펫, 소수 찾기 — 약수와 순열 후보 및 중복 제거
- [ ] 피로도, 이모티콘 할인행사 — 선택 순서와 조합의 전체 탐색
- [ ] 구명보트 — 정렬 후 양 끝 선택이 안전한 이유 설명
- [ ] 큰 수 만들기 — 앞자리 선택과 단조 스택 연결
- [ ] 조이스틱, 점프와 순간 이동 — 이동 전략의 예외와 선택 근거 확인
- [ ] 호텔 대실, 디펜스 게임 — 정렬·힙과 그리디 결합

### 3단계 · 실전 응용

- [ ] 프로그래머스 양궁대회, 수식 최대화 — 후보 생성과 동률 처리
- [ ] 프로그래머스 단속카메라 — 구간의 끝점을 이용한 선택 증명
- [ ] 그리디가 실패하는 작은 반례를 직접 만들고 완전탐색으로 검증

## 점검할 것

- [ ] 후보 개수 × 후보당 검증 비용을 입력 제한과 비교한다.
- [ ] 순서와 중복 허용 여부를 문제 조건에 맞게 구분한다.
- [ ] 그리디 선택을 정당화하고, 반례를 찾지 못한 것만으로 증명하지 않는다.

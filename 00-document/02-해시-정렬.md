# 02. 해시 · 정렬 트레이닝

> 목표: 데이터의 조회·집계와 정렬 기준을 설계하고, 기업 코딩테스트에서 자주 나오는 조건과 예외를 독립적으로 처리한다.

## 핵심 개념

### 해시

- **해시**는 키를 해시값으로 변환해 데이터를 저장하고 찾는 방법이다. 서로 다른 키가 같은 해시값을 갖는 충돌도 발생할 수 있으므로 충돌을 처리해야 한다.
- Python의 `dict`와 `set`은 해시 기반 자료구조다. 삽입·조회·삭제는 **평균적으로** O(1)이지만, 충돌이 많으면 최악의 경우 O(n)이 될 수 있다.
- `dict`는 키와 값을 연결하고, `set`은 중복을 제거하거나 포함 여부를 확인할 때 유용하다. 키와 집합 원소는 해시 가능해야 한다. 예를 들어 튜플은 내부 원소도 모두 해시 가능해야 키로 쓸 수 있다.
- `Counter`는 빈도 집계에, `defaultdict`는 키가 없을 때의 기본값 처리에 편리하다. 개수가 0이 된 키를 계속 보관할지 삭제할지 문제에 맞춰 결정한다.

### 정렬

- `sorted(iterable)`은 정렬된 새 리스트를 반환하고, `list.sort()`는 원래 리스트를 정렬하며 `None`을 반환한다. Python의 일반적인 정렬 시간복잡도는 O(n log n)이다.
- `key` 함수로 정렬 기준을 지정한다. 예를 들어 `key=lambda x: (-x[1], x[0])`은 두 번째 값을 내림차순, 첫 번째 값을 오름차순으로 정렬한다.
- Python 정렬은 **안정 정렬**이므로 키가 같은 원소는 원래의 상대 순서를 유지한다. 동률 규칙을 문제에서 명시했다면 정렬 키에 정확히 반영한다.

## 단계별 훈련

### 1단계 · 기초 개념과 직접 구현

`dict`, `set`, `Counter`, `sorted`, `sort`의 동작을 작은 예제로 확인하고, 해시 충돌과 정렬 기준을 손으로 추적한다.

- [ ] 해시 직접 구현 ① — 문자열 목록에서 각 원소의 등장 횟수 세기
- [ ] 해시 직접 구현 ② — 두 목록의 개수를 비교해 부족한 원소 찾기
- [ ] 해시 직접 구현 ③ — 키별 값을 모으고 조건에 맞는 그룹 집계하기
- [ ] 해시 직접 구현 ④ — 두 수의 합을 만족하는 쌍의 존재 여부 찾기
- [ ] 숫자·문자열·튜플을 단일 및 다중 조건으로 정렬하고 동률 순서 확인
- [ ] 프로그래머스 완주하지 못한 선수 — 중복 이름의 빈도 비교
- [ ] 프로그래머스 K번째수 — 슬라이스 범위와 정렬 후 인덱스 확인
- [ ] 프로그래머스 두 개 뽑아서 더하기 — 조합, 중복 제거, 정렬

### 2단계 · Lv.2 해시 패턴

- [ ] 전화번호 목록 — 접두어 판별과 정렬 또는 해시 활용
- [ ] 의상 — 종류별 빈도와 선택하지 않는 경우를 포함한 조합
- [ ] 할인 행사 — 고정 길이 구간의 빈도 비교와 갱신
- [ ] 롤케이크 자르기 — 양쪽 종류 수를 효율적으로 관리
- [ ] 오픈채팅방 — 최종 닉네임을 저장한 뒤 메시지 생성
- [ ] 후보키 — 조합별 유일성과 최소성을 분리해 검사

### 3단계 · Lv.2 정렬 패턴

- [ ] H-Index — 정렬된 인용 횟수와 조건의 경계 확인
- [ ] 가장 큰 수 — 이어 붙인 결과를 기준으로 정렬하고 모두 0인 경우 처리
- [ ] [3차] 파일명 정렬 — 문자열 파싱, 대소문자 비교, 안정 정렬
- [ ] 튜플 — 집합 크기 순 정렬과 원소 복원
- [ ] 호텔 대실 — 시간 순서와 종료 시점 처리

### 4단계 · 실전 응용

- [ ] 프로그래머스 베스트앨범 — 장르별 집계와 여러 단계의 동률 정렬
- [ ] 프로그래머스 보석 쇼핑 — 해시 빈도와 투 포인터 결합
- [ ] 유형을 보지 않고 새 문제를 풀고, 해시·정렬 외의 대안과 시간복잡도를 비교
- [ ] 대표 문제를 다음 날과 7일 뒤 다시 풀고 Java의 `HashMap`, `HashSet`, 정렬 기준으로 구현

## 점검할 것

- [ ] 키에 중복이 있을 때 덮어쓰기와 빈도 누적 중 무엇이 필요한지 구분한다.
- [ ] 없는 키, 빈 입력, 중복값, 빈도 0 및 동률 조건을 확인한다.
- [ ] 정렬 기준의 우선순위와 오름차순·내림차순 방향을 예제로 검증한다.
- [ ] 전체 시간복잡도에 정렬뿐 아니라 순회, 키 생성, 후보 검사 비용도 포함한다.
- [ ] 해설이나 힌트를 본 문제는 독립 풀이와 구분해 기록하고, 해설을 덮은 뒤 다시 구현한다.
